# 种草软件 UI 评审 · 2026-10-24

> 对象：`feat/calendar-card-ui` @ a7d8312，390/375 宽手机视口，`?demo` 数据
> 方法：五个 Tab 全部实机截图 + 浏览器实测几何与对比度，不靠目测
> 背景：借 PostgreSQL 共享状态 + x86 部署这次迁移一起做

---

## 总体评分：5.8 / 10（需改进）

| 维度 | 分 | 一句话 |
| --- | --- | --- |
| 概念 / 立意 | **5** | 规格里那个「城市食册」的 idea 没有落到实现里 |
| 哲学一致性 | 5 | 实现（白底暖琥珀）和已批准的规格（暖雾底 + 椒红）是两套系统，两套的残留同时在跑 |
| 视觉层级 | 5 | 标题 / 正文只差 1.5 倍，9 个字号没有角色分工 |
| 细节执行 | 6 | 间距 7 个值、圆角 4 个值都不成系统；有重复 CSS 规则和死类 |
| 功能性 | **4** | 想去页一半首屏在看筛选器；迁移带来的共享语义完全没有界面 |
| 创新性 | 5 | 白底 + 单暖色 + 满屏 pill，是 2026 年通用收藏 App 的默认长相 |

概念 ≤5，按评审规则总评封顶 6.0。

**这个设计说了什么？** 现在讲不出来。遮住所有文字，这五个屏幕可以是读书笔记 App、待办清单、旅行收藏夹里的任何一个——换个产品名完全成立。`docs/UI-REDESIGN-SPEC.md` 里写过一个能讲出来的 idea（「城市食册」：冷矿物底降疲劳、椒红只做单点强调、真实食物图承担食欲），但 `b8789a3 feat(ui): rebuild frontend as content-first white + amber` 之后，实现换成了白底 + 暖琥珀。那一版在「别让界面自己耍花活」这点上是对的，代价是把唯一的 idea 一起删掉了。

---

## 优点（Keep）

- **五栏信息架构稳**。收件箱→想去→日历→已去过→我的，和 PRD 的闭环一一对应，没有多余入口。
- **白底 + 内容承担颜色**这个判断本身是对的。`styles.css` 顶部那段注释（早期的厚黏土阴影、粗描边、染色底才是显廉价的原因）是一次真实的、说得出理由的设计复盘。
- **语义 token 已经建起来**。颜色全走 `@theme`，Tailwind 的 `emerald-*` / `zinc-*` / `stone-*` 被统一重映射，换色时全站会一起动——这是后面所有改动能便宜做的前提。
- **深色文字配琥珀填充**这个取舍是清醒的：知道琥珀扛不住白字，于是全局用 `--color-on-accent` 深色（8.58:1）。
- 触控目标普遍 ≥44px，`aria-label` 覆盖了 icon-only 按钮，日历格有 `aria-pressed`。

## 问题（Fix）

### 1. 想去页一半的首屏在看筛选器 — ⚠️致命

- **当前**（实测 375×812）：顶栏 78 + 搜索 52 + 三行筛选 chip 150 + 排序行 44 = **324px**，之后才是第一条内容。去掉顶栏和底栏，可用视口 660px，**49% 被消耗在看到任何一条店之前**。
- **问题**：想去是主行动页。24 条线索、7 个常驻筛选 chip 折成三行常年占着位置，而大多数时候一个都没选。筛选是偶发动作，内容是每次都要的。
- **修复**：搜索框和「筛选」按钮并一行（42px）；chip 收进 bottom sheet；只有**已选中的**筛选以可点掉的 token 形式占一行（没选就不占）。顶栏去掉装饰副标题，78 → 56px。合计 324 → **153px**，内容占比 51% → 77%。

### 2. 列表密度配不上「24 条里挑一个」这件事 — ⚠️致命

- **当前**：`.place-card` 行高 138px，缩略图 130px 几乎顶满行，但一行只承载「名字 + 一行 meta + 两个标签」。重点卡 310px 只放一条。24 条文档总高 4,266px。
- **问题**：这个产品的核心动作是扫一遍挑一个。一屏 4.4 条，挑一次要滚 6 屏。Beli / Mapstr 这类同场景产品一屏 6–8 条。另外那张 310px 的重点卡不是推荐，只是 `updatedAt` 排第一的那条——规格自己也写明了「不能写为你推荐」，那它凭什么占两条半的位置。
- **修复**：缩略图 130 → 76px，行高 138 → 97px，重点卡取消（改成列表里一条「最近」分隔）。首屏可见 2.2 → 5.2 条，滚动中 4.4 → 6.8 条，列表总长少三分之一。信息一条不减。

### 3. 迁移把数据变成两人共享了，界面上一个字都没说 — ⚠️致命

这是「乘着迁移一起做」最该做的一件事。`server/state-repository.mjs` + `/api/state` 的 revision 机制已经上线，但界面还是按单机单人写的：

- **没有同步状态**。保存中 / 已保存 / 失败 / 离线，一个都看不到。`docs/UI-REDESIGN-SPEC.md` §8.2C 明确要求过「保存线索 → 正在保存 → 已保存」的按钮状态形变，没实现。
- **冲突是静默的**。`src/App.jsx:186` 的 `adoptRemoteState` 在 409 之后把对方的最新 state 整个换进你的视图，**零提示**。小张在另一台设备改了两条，你这边列表悄悄变了，你不知道发生过什么。
- **二次冲突只有一句 toast**（`src/App.jsx:199`「请刷新后重试」），2.4 秒后消失，用户的那次操作已经丢了。
- **离线没有路径**。断网时写操作抛错 → toast → 操作丢失，没有重试、没有排队。
- **`addedBy` 的意义变了**。单机时它是个备注；两人共享之后它是「这条是谁的主意」，但它现在长成一个 76px 宽的「小王添加」胶囊，在 375px 的行里和店名抢空间。
- **修复**：顶栏右侧常驻同步点（已同步 / 正在保存 / 离线，6px 圆点 + 两到四个字）；远端更新顶出一条可见的、要人点掉的条，不是 toast；`addedBy` 缩成 21px 首字母圆点，横向空间还给店名；提交按钮按规格做 idle→loading→success 三态。

### 4. 两套强调色同时在跑 — ⚡重要

- **当前**：`--color-accent` 是琥珀 `#f2b33d`，但 `.chip:hover`、`.cal-cell:hover`、`.cal-cell-today` 里留着上一版规格的椒红 `rgba(227,74,44,…)`（`src/styles.css:617,851,855`）。日历的今天是椒红描边 + 琥珀点。
- **修复**：选一个。见下面第 9 条的建议。

### 5. 筛选计数的对比度 1.86:1，而且是一条重复规则造成的 — ⚡重要

- **当前**：`src/styles.css:303-309` 把 `.filter-chip-active .chip-count` 定义了**两次**。第一条 `rgba(42,32,22,.55)` 是对的；第二条 `rgba(255,255,255,.62)` 白字压琥珀 = **1.86:1**，覆盖掉了第一条。实测确认这是全站唯一一处正文级对比度不达标。
- **修复**：删掉第二条。（顺带：文件顶部注释写的「2.15:1」也偏乐观，实测 1.86:1。）

### 6. 每页标题说两遍 — ⚡重要

- **当前**：顶栏「大标题 + 一句装饰副标题」，正文里再来一次「区块标题 + 一句装饰副标题 + 右侧计数胶囊」。收件箱最明显——「先收起来，之后再整理」在顶栏和卡片里**一字不差地出现两次**，加起来吃掉约 130px。
- **问题**：`topBarSubtitle()`（`src/App.jsx:627`）里「24 条灵感，等一次出发」「没去也没关系，改期、放回想去或直接放下」这类句子是情绪文案，不是状态。规格第 10 节自己写了「空状态提供下一步动作，不写情绪化占位句」。
- **修复**：顶栏只留「标题 + 真实计数」；装饰副标题全删；区块标题降为 13px 的一行（`12 条 · 按收藏时间`），和右侧排序控件同一行。

### 7. 收件箱的主路径被两个可选字段撑开 — ⚡重要

- **当前**：链接、标题、备注三个大输入框纵向堆叠，之后才是添加人和「保存线索」。PRD 的硬目标是 15 秒存一条。
- **修复**：链接 + 添加人 + 保存线索三个控件就到底，「补充店名、备注」折成一行可展开。另外收件箱页右上角那个「去收件箱」的 `+` FAB 是自指的，在本页删掉。

### 8. 排版和间距系统失控 — 💡优化

实测一个想去页上：

- **字号 9 个**：12 / 13 / 14 / 15 / 16 / 17 / 20 / 24 / 26（不含 emoji 占位的 60、92）。规格定义了 7 个角色，实现里 13、14、15 三个都在当「次级文字」，没有分工。页面标题 26px ÷ 正文 17px = **1.5 倍**，评审基线要求 ≥2.5 倍，层级是扁的。
- **gap 7 个**：4 / 6 / 8 / 10 / 12 / 14 / 16 —— 6、10、14 不在任何网格上。
- **圆角 4 个**：14 / 16 / 18 / 30 —— 16 和 18 在同一屏上肉眼分不出，等于两个值做一件事。规格写的是 10 / 14 / 20 / 24，两边都没对上。
- **一屏 78 个全圆角元素**：chip、按钮、搜索框、FAB、缩略图、计数全是 pill。形状不再区分功能。
- **修复**：字号收到 6 档（12 标签 / 13 元数据 / 15 次级 / 17 卡片标题 / 21 页面标题 / 28 大数字），间距只用 4 / 8 / 12 / 16 / 24 / 32，圆角只用 5（标签）/ 12（缩略图）/ 14（卡片与按钮）/ pill（只给筛选和搜索）。

### 9. 琥珀这个强调色是个死胡同，而且正好是 AI 默认长相 — 💡优化

- **算术**：`#f2b33d` 配白字 **1.86:1**，所以全站被迫用深色 `#2a2016` 当「on-accent」，琥珀当文字时又要换成另一个更深的 `#96631f`。一个强调色拆成三个变体才能用，这是在跟颜色本身较劲。
- **辨识度**：白底 + 单一暖琥珀 + 满屏圆角，是现在生成式工具最常见的几种长相之一。它不丑，但它和「上海美食决策」这个题材没有关系——换成记账 App 一样成立。
- **修复建议**：回到规格原本批准的椒红，但把填充色沉一档：

  | 用途 | 值 | 对比度 |
  | --- | --- | --- |
  | 填充（主按钮、计数徽标），白字 | `#C33C22` | **5.26:1** ✓ |
  | 描边 / 图标 / 焦点环，在白底上 | `#E34A2C` | 3.98:1（图形 ≥3:1 ✓） |
  | 极淡底（已选 token、提示条） | `#FDF0EC` | — |

  一个色、两档明度，白字能用，不再需要三个变体。同时强调色收回到只出现三处：主操作、未处理计数、需要注意的状态；底栏选中块改成墨色短条（规格本来就写的 ink 滑块），日历 today 改成墨色描边。

### 10. 死代码与 dev/prod 不一致 — 💡优化

- **死 CSS**：`chip-selected`、`toggle-button`、`toggle-active`、`wish-card`、`wish-card-actions`、`empty-state-icon` 定义了但没有任何地方引用。
- **`vite.config.js` 里 `publicDir: false`**，所以 `npm run dev` 下 `/mascot.svg`、`/icon.svg`、`/manifest.webmanifest` 全部 404（返回 index.html，`content-type: text/html`）。生产由 `server.mjs` 自己发这些文件，所以线上是好的——但 dev 预览里吉祥物全是碎图，开发时看到的和用户看到的不是同一个东西。
- **修复**：删死 CSS；`publicDir` 改回默认（或指到 `public`），`build` 时再按需排除。

### A · 卫生

- 删掉重复的 `.filter-chip-active .chip-count`。白字压琥珀 **1.86:1**（源码注释写的 2.15:1 偏乐观），它覆盖了前面那条正确的深色规则。
- 审计只扫了想去页，漏了 12 处。全站逐 Tab 重扫后一并修掉：
  - `.details-panel summary` 用 `--color-accent` 当标题色 = 1.86:1 → 改墨色。顺带把强调色从「区块标题」这个位置收回来。
  - `.segmented-option[data-active]` 白字压琥珀 = 1.86:1 → 改 `--color-on-accent`（8.58:1）。
  - `.cal-cell-today` / `.chip:hover` / `.cal-nav:hover` 把 `#d99a28` 压在琥珀浅底上 = 2.25:1 → 改 `--color-accent-ink`（4.73:1）。
  - `.mini-label` / `.empty-state` / `.loading-screen` 的 `#8a847a` = 3.71:1 → 改 `--color-zinc-500`（4.9:1）。
- 残留的上一版椒红 `rgba(227,74,44,…)` 六处统一：描边走新 token `--color-accent-rim` / `--color-accent-rim-strong`；撤销按钮的红升格为语义色 `--color-red-500`（白字 4.91:1），不再是第二个游离的品牌色。
- 删死 CSS：`chip-selected`、`empty-state-icon`、`toggle-button`、`toggle-active`、`wish-card` 及其五条后代规则。
- `vite.config.js` 的 `publicDir: false` 改成 `"public"`。此前 `npm run dev` 下 `/mascot.svg`、`/icon.svg`、`/manifest.webmanifest` 全部 404，开发时看到的是碎图。生产由 `server.mjs` 兜底，行为不变。
- 顺手补上两个一直没达标的触控目标：`.sort-chip`、`.cal-nav` 40 → 44px。

### B · 首屏与密度

- **顶栏 78 → 56px**，单行：吉祥物 · 标题 · 真实计数 · 同步点 · 新建。`topBarSubtitle()` 换成 `topBarCount()`，情绪文案（「24 条灵感，等一次出发」「没去也没关系…」）全部删掉。
- **`SectionHead` 从「24px 大标题 + 一句文案 + 计数胶囊」压成一行** 13px 标题 + 计数。
- **筛选收进 bottom sheet**：`ChipFilters` → `FilterBar` + `FilterSheet`。列表上方只留搜索 + 筛选按钮（带已选计数徽标）；已选中的筛选以可点掉的 token 单独占一行，没选就整行不存在。sheet 走 `createPortal` 挂到 body（`.filter-stack` 有 transform，会把 `position: fixed` 圈住），有 `aria-modal`、Escape 关闭、关闭后焦点归位。
- **列表行 138 → 97px**：缩略图 130 → 76，靠 1px 分隔线而不是留白分组。
- **`addedBy` 从 76px 的「小王添加」胶囊变 22px 字圆点**，完整说法留在 `title` 和 `sr-only` 里，读屏和长按都拿得到。省下的横向空间还给店名。
- **重点卡 310 → 255px**：封面 `aspect-ratio` 从 20/13 改 2/1。规格 §6.2 要的是一张重点卡，保留；但它不该占两条半列表项的位置。
- **收件箱主路径收成「链接 + 添加人 + 保存」**，标题和备注折进 `<details>`，默认不占位置。面板里和顶栏重复的那句「先收起来，之后再整理」删掉。收件箱页右上角自指的 `+` 也去掉。
- 删掉日历的「日历视图」eyebrow 小标签。

### C · 共享状态

- **常驻同步点**（`SyncDot`）：已同步 / 正在保存 / 离线 / 保存失败 / 演示数据。正常时只留一个 7px 圆点把空间让给标题，需要注意时才带文字；`role="status"` + `aria-live="polite"`。
- **远端更新提示条**（`RemoteChangeBar`）：`adoptRemoteState` 在 409 重放时会把对方的最新状态整个换进当前视图——以前这一步完全无声，用户只看到列表莫名其妙变了。现在顶出一条要人点掉的条。
- **`persist` 报告保存状态**：saving → synced；失败时区分离线和出错。409 由 `saveStateMutation` 重放，不记为失败。
- **离线监听**：`online` / `offline` 事件 + 启动时的 `navigator.onLine`。
- 提交三态：`StatusButton`（idle → pending → success）本来就覆盖了「安排日期」类流程，快速保存有 pending + 成功 toast；这次补的是全局那一层，每一次写入都有反馈。
